# 연구 문제를 소프트웨어로 개선한 경험

## 문제 정의

CQD 광검출기 학부연구에서 여러 DC bias·AC amplitude 조건을 설정하고 데이터를 정리하는 작업을 반복했습니다. 개별 CSV의 피팅과 그래프 작성에도 시간이 소요돼 측정·분석·표시 단계를 각각 개선했습니다.

| 발견한 문제 | 구현한 개선 | 근거와 확인 범위 |
|---|---|---|
| 장비 조건 설정과 저장을 반복 | MFIA 자동 측정 SW | 1.4의 610포인트 약 75분 사용자 실행 사례. 패키지 테스트 74개 통과/1 skip |
| 여러 바이어스 CSV의 수동 피팅과 단위 관리 | DLCP/EIS 분석 SW | 17.2 테스트 73개와 EXE 합성 데이터 자가검사 통과 |
| 바이어스마다 회로가 달라 비교가 어려움 | 공통 등가회로 적용 및 피팅 진단 | 회로의 일관성과 파라미터 식별 가능성을 함께 확인 |
| 조건별 그림 정리와 저장 반복 | 독립 PLOT SW | 2.1.1 테스트 33개 및 GUI·EXE 검사 통과 |

## 직접 맡은 역할

- 측정 현장에서 반복 작업과 오류가 발생하기 쉬운 부분을 발견하고 요구사항을 정리했습니다.
- 전압 기준, AC amplitude 표현, 주파수·용량·면적 단위와 출력 항목을 확인했습니다.
- AI 코딩 도구로 구현·수정·테스트 작성을 보조하고, 결과를 검토하며 개선을 반복했습니다.
- Windows 실행파일을 패키징하고 소스 테스트와 패키징 후 검증의 범위를 구분했습니다.

## 기술적 판단

원본 측정 파일과 분석 결과를 구분하고 조건과 설정을 추적하도록 개발했습니다. EIS 최적화가 수렴한 경우에도 Cj/Cother의 분리가 유일하거나 물리적으로 타당한지는 별도로 확인해야 합니다. 단위·부호·계산 조건과 결과 크기를 검토하고 GUI 로딩·오류 표시·내보내기 같은 실제 사용 흐름을 개선했습니다.

## AI 활용을 설명하는 방식

AI는 코드 작성과 디버깅을 돕는 도구로 사용했습니다. 연구 문제 정의 → 기능 요구사항 → 구현 검토 → 검증 → 실제 적용의 과정과, 연구자가 직접 판단해야 하는 측정 조건·결과 해석을 함께 설명합니다.

## 성과 표현의 기준

610포인트 약 75분은 특정 조건의 연구 사용 사례입니다. 과거 약 101분 사례와 단순 비교한 수치를 통제된 SW 성능 개선율로 표시하지 않습니다. R² 목표와 측정 정확도도 구분합니다. 연구실 전체 도입률·절감 인력·정확도 개선율은 별도 기록 없이 수치화하지 않습니다.

## 포트폴리오 소개 문장

> CQD 광검출기 연구에서 반복적인 측정 설정과 데이터 처리 문제를 발견하고, AI 코딩 도구를 활용해 MFIA 자동 측정·DLCP/EIS 분석·그래프 시각화용 Windows SW 3종을 개발했습니다. 측정 조건과 단위 관리, 피팅 진단과 결과 저장 기능을 개선하고 자동 테스트 및 패키징 검증으로 확인 가능한 범위를 기록했습니다.
